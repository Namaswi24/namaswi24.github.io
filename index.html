Technological Developer Intern, Core Tech

The firm runs its daily pipelines, including time-critical trading scripts, through a 20-year-old in-house job scheduler. Its monitoring UI showed where a job was but not whether it was healthy, so host problems the alerting system already knew about only reached users when a job failed. I built the path that puts those alerts on the job's own row.

Job 1234 Running host-17: high memory

Illustrative example. Job and host names are made up.

  1. Alerting webhook
  2. Alert Receiver
  3. Kafka
  4. Redis
  5. Job row, live
  • Built a new Alert Receiver service in Java that validates and filters incoming alerts, normalises host names, and derives a stable alert ID so every downstream write is an idempotent upsert.
  • Routed alerts through the scheduler's existing Kafka, SQL Server and Redis pipeline instead of building a parallel one, so they inherit the same durability and delivery path as job updates. The change added one service and two topics and extended four existing services.
  • Designed a state-aware correlation rule that attaches an alert only when its host matters for the job's current state, and placed each check where the data already lives to avoid repeated network calls.
  • Proposed the runtime anomaly half of the project, which flags jobs running past a normal band learned from their own history.
Three design decisions

Publish first, then remember

The receiver records an alert as active only after Kafka confirms the publish. Doing it the other way round could leave it tracking an alert no downstream service ever received, with nothing to correct it later.

Don't rely on the "cleared" signal

The alerting system doesn't reliably announce when an alert clears. A reconcile loop compares firing alerts against the active set every 20 seconds, resolving stale ones and recovering missed ones.

Say yes to alerts you ignore

The sender retries anything that isn't a 2xx response. Out-of-scope alerts get a 200 and are dropped, so they don't come back as retries.
